The first implementation requested an entire30minute data block before slicing scored epochs. Large transfers stalled, so acquisition was changed to fetch only the selected annotated epochs in bounded byte ranges. Selection remains the first30minutes and first10complete30second epochs perW/S1/S2, with recorded channel requirements unchanged. Each range includes a1second resampling margin where available. Annotation parser correction: the Position column is optional in CAP exports. n2/n3 initially produced zero eligible counts because the first implementation assumed that column. The final reader locates SLEEP-S0/S1/S2 explicitly and uses the adjacent time/duration fields. Exclusions from that initial parser are superseded by the final manifest. n4 independently has a long unscored lead-in; the full-record scored-epoch amendment remains explicit and is not falsely attributed to n2/n3.
EDF unknown-length handling: n13 and n14 encode -1 in the EDF number-of-records header, which is an unknown count rather than an empty recording. The final reader derives the count from the validated HTTP Content-Range total file length minus header length, divided by the per-record byte count, requiring an exact integer. No epoch timing is guessed or shifted. The initial 'no eligible scored stages' messages for these files are superseded by this correction and the final manifest.
